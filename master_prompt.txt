# PROJECT: ثانوية عامة Study OS — Personal Study Management Website

You are Claude Code acting as a senior full-stack engineer, product designer, UX designer, and software architect.

I want you to BUILD a complete personal study-management web application for my Egyptian Thanaweya Amma (ثالثة ثانوية عامة) 2026/2027 study year.

This is not a request for a mockup, wireframe, product description, or partial prototype.

I want an actual working website with a polished UI, persistent data, configurable schedules, study tracking, Pomodoro functionality, revision management, analytics, and all other functionality described below.

You should make sensible engineering decisions yourself, but DO NOT remove important functionality simply because it is complex. If a feature is difficult, implement a simpler working version first and structure the code so it can be expanded later.

The application is being designed for one primary user.

Student:

* Grade: ثالثة ثانوية عامة

Desired sleep:

==================================================
2. CORE PRODUCT PHILOSOPHY
==========================

The website should NOT feel like a generic calendar.

It should feel like a personal "Study Operating System".

The application should answer:

* What should I study today?
* What should I study next?
* How much have I completed?
* Am I falling behind?
* What should I revise?
* Which subjects are receiving enough attention?
* What mistakes am I repeatedly making?
* How much focused work have I actually done?
* How many questions am I solving?
* How efficiently am I solving?
* What do I need to catch up on?
* What should I do when I miss a day?
* When should I take breaks?
* When can I relax without feeling guilty?

The system should prioritize:

1. Consistency
2. Curriculum progress
3. Active problem solving
4. Revision
5. Exam preparation
6. Sustainable workload
7. Sleep and recovery

Avoid creating a system that rewards simply sitting at the computer for many hours.

"Focused work completed" should be more important than "time spent with website open."

* estimated duration
* deadline
* subject

Rules:

1. Respect maximum daily workload.
2. Prefer catch-up blocks.
3. Do not eliminate all free time.
4. Avoid scheduling excessive difficult subjects consecutively.
5. Prioritize overdue/high-priority tasks.
6. Spread backlog across several days if necessary.
7. Tell the user when the backlog is too large to fit within current settings.

Do not silently overload the user.
